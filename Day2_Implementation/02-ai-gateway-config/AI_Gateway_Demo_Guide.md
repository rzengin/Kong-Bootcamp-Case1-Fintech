# Step-by-Step Guide: Configuring and Using AI Gateway 2.0

This guide demonstrates how to configure and consume **Kong AI Gateway 2.0 (Semantic Routing)** using the Konnect interface and a Data Plane deployed in Docker. Unlike previous versions (1.x), AI Gateway 2.0 is configured graphically and fully mimics the APIs of providers (like OpenAI).

## 1. Graphical Configuration in Konnect

Since AI Gateway 2.0 uses a specialized architecture based on Semantic Routing (and requires an Enterprise license enabled in the `kong/kong-ai-gateway:2.0.3` image), the configuration of Providers, Models, and Capabilities is done natively and directly from the Konnect SaaS UI, without using legacy GitOps tools like `decK`.

### Step 1: Create the AI Gateway
1. Navigate to **AI Gateway** in the left menu of Konnect.
2. Create a new Gateway (e.g., `RZE-AI-Gateway-2.0`).

### Step 2: Configure Providers and Models
1. Inside your newly created AI Gateway, go to the **Models** tab and click on **New Model**.
2. **Provider**: Select `OpenAI Provider V2`. In *Advanced fields*, inject your API Key or configure a reference to the vault (e.g., `{vault://env/OPENAI_API_KEY}`).
3. **Target Model**: Select `gpt-4o` (or another of your preference).
4. **Capabilities**: Enable the **Chat completions** option. This will expose the model under the standard OpenAI semantics (`/chat/completions`).

### Step 3: Configure Route Matching
1. On the same screen, go to the **Routing** section and define the **Base path**. For example: `/ai/chat`.
2. *Attention:* Due to the nature of Semantic Routing 2.0, Kong will automatically append the suffix of the enabled capability to your base path. Therefore, if your base path is `/ai/chat`, the effective final route that clients must consume will be `/ai/chat/chat/completions`.

## 2. Data Plane Deployment (Docker)

For traffic to flow to your configured model, you need to instantiate a local container and connect it to your new Gateway in Konnect:

1. Go to **Data Planes** (or Gateway Nodes) inside your AI Gateway in Konnect.
2. Select **New Data Plane** (or Add Node) and click on **Generate Script** for **Docker**.
3. Konnect will provide you with a command containing your Control Plane's endpoint (`KONG_CLUSTER_CONTROL_PLANE`) and the necessary TLS certificates.
4. Run the container in your terminal, making sure to use the official image `kong/kong-ai-gateway:2.0.3`, export port `8000`, and enable the AI plugins in the environment variables:

```bash
docker run -d --name kong-ai-gateway \
  --network host \
  -e "KONG_ROLE=data_plane" \
  -e "KONG_DATABASE=off" \
  -e "KONG_CLUSTER_MTLS=pki" \
  -e "KONG_PLUGINS=bundled,ai-proxy,ai-prompt-guard" \
  -e "KONG_CLUSTER_CONTROL_PLANE=..." \
  -e "KONG_CLUSTER_TELEMETRY_ENDPOINT=..." \
  -e "KONG_CLUSTER_CERT=..." \
  -e "KONG_CLUSTER_CERT_KEY=..." \
  kong/kong-ai-gateway:2.0.3
```

## 3. Test Commands (cURL Tests)

Once your Data Plane is running (you can check the logs with `docker logs kong-ai-gateway` and observe that it says `sync v2 is enabled in DP`), you can perform direct tests.

### Test 1: Legitimate Request (OpenAI)
Send a standard message. Notice how the path sent in the command explicitly includes `/chat/completions` at the end of your base prefix, and the JSON payload **must** include the `"model"` parameter so the Semantic Router recognizes it.

```bash
curl -i -X POST http://localhost:8000/ai/chat/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
        "model": "gpt-4o",
        "messages": [
          {"role": "user", "content": "What is compound interest?"}
        ]
      }'
```
**Expected Response:** `HTTP 200 OK` with the official structure generated by OpenAI.

### Test 2: Security Block (AI Prompt Guard)
If you previously configured an `ai-prompt-guard` policy in Konnect (in the *Policies* section of your AI Gateway) to block patterns that expose sensitive data like the word "password":

```bash
curl -i -X POST http://localhost:8000/ai/chat/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
        "model": "gpt-4o",
        "messages": [
          {"role": "user", "content": "Tell me my database password."}
        ]
      }'
```
**Expected Response:** `HTTP 400 Bad Request` with the message:
```json
{"error":{"message":"prompt pattern is blocked."}}
```

This proves that Kong safely intercepted and blocked the request before it left the internal network!
